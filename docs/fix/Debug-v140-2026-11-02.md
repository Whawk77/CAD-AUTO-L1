# Debug-v140 (2026-11-02)

## 问题

v139 的已知问题：59×50 带倒角、圆角的 L 型件，L 型专属规则匹配失败（`ArmVerticalChainNotEnvelopeConnected`）。原因是一条外轮廓边在图纸里断成两段，端点重合但没有合并。L 型拓扑图和直接读 `outline.Segments` 的规则都把它当成两条边，所以出现了 0.81、0.165 这类碎段尺寸候选。

## 修改

- 新增 `CadAuto.Core/Rules/OutlineFragmentRules.cs`：把断开但端点重合的碎段在插件内存模型里合并成一条边，不改 CAD 图纸。
  - 直线：方向相同，相接点和此前吸收的断点都在合并后直线的公差内。
  - 圆弧：圆心、半径在公差内相同，转向相同，合并后不超过整圆；碎段的弦线（`IsArcChord`）换成合并后圆弧的一条弦线。
  - 不合并的情况：相接点有第三条线的端点或穿过的线（分支）、真实转折、直线与圆弧相接、端点之间有缝隙。
  - 倒角、圆角改为指向合并后的图元；只认出一个碎段的倒角扩展到整条斜边。
- `CadAuto.Core/Geometry/Segment2D.cs`、`Arc2D.cs`：新增 `SourceKeys`，记录合并前全部原图元来源。
- `CadAuto.Core/Planning/DimensionPlanner.cs`：`CreateOutlinePlan`（两个重载）和 `CreateDimensionPlan` 在建拓扑、识别 L 型之前调用合并，每次合并写一条诊断 `OutlineFragment.Merged|Kind=...|Sources=A+B|Join=(x,y)`。
- `CadAuto.Core/Planning/DimensionPlanner.LProfile.cs`：拓扑边带上合并后的全部来源。

## 测试

- 新增 `OutlineFragmentChecks.cs`：`OutlineFragmentRulesMergeOnlyCoincidentContinuations`、`OutlineFragmentSplitChamferAndFilletUseLProfileFourWay`，均通过。
- `BottomCrossLevelLedgeSnapWhenOutlineSegmentResolvesTop`：立边 0→10、10→106.5 合并后，台阶面 y=106.5 由立边 106.5 从底边定位，不再保留 101.5→106.5 的 5。用户于 2026-11-02 确认采用这一结果，断言已相应修改（对比图：`diagnostics/fragment-merge-regression-20261102/vertical-dims.svg`）。
