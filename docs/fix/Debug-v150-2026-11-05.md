# Debug-v150 — 2026-11-05

- 标识：46b2069e62a24aea95eab43b15fec2ba；DLL 版本 1.0.150.0。

## 问题

v149 实测（run 20261105214535669，带 3×3 台阶的倒 T 托压块）：底部 5、25、28、50 四层尺寸和 TY 的"淬火"、"CNC加工"文字、1.6 粗糙度重叠，但没有移动，诊断里也没有 `SupportBlock.CalloutShift`。

## 原因（推断）

v149 用 `GeometricExtents` 求 ASD 新建尺寸的外框。尺寸在同一事务里刚创建，事务提交前尺寸块还没生成，外框读取失败或不对，所以没有障碍物，也就不会移动。v149 在这种情况下也不写诊断，所以看不出原因。

## 改动

- `SupportBlockCalloutAdjuster`：ASD 尺寸的外框改为按尺寸自身的几何计算，不再读 `GeometricExtents`。范围包括两个尺寸界线原点、尺寸线两端、文字框（按字高和文字长度估算，默认文字位置取尺寸线中点），并沿尺寸线外扩一个箭头长度。TY 的文字和粗糙度块是已提交的旧对象，仍用 `GeometricExtents`。
- 一组 TY 标注里只要有能求出外框的文字或块就参与判断，不再要求全部都能求出。
- 每次托压块 ASD 都写一条 `SupportBlock.CalloutCheck|Obstacles=..|Groups=..|Entities=..|Shifted=..`，没有移动时也写，方便定位原因。

## 验证

- 全套测试：executed=218 passed=201 failed=17，均为既有历史失败。
- CAD 侧需实测：同一张图用 v150 跑 ASD，看 TY 文字和粗糙度是否移到 50 下方，并检查诊断里的 CalloutCheck 记录。
- 这件零件的 T 型判定（3×3 台阶导致 NotT）还没处理，等用户决定台阶怎么标。
